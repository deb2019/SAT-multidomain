SAT threshold-switch audit pilot, 26 November 2026
Three temporal datasets, 17 realised batches, original logistic scorer, false-positive cost 1, false-negative cost 5. Fixed budgets 10, 25 and 50 are separate alternatives, not sequential looks. Results are retrospective operating characteristics; no prospective audit or new annotations were performed.

Run python audit.py in this directory (numpy, pandas, scipy) to reproduce pilot_results.csv from the included batch counts and original published cost rows. To rebuild counts, put each original dataset under data/ and run python prep.py diabetes, python prep.py bank, python prep.py fraud. prep.py uses the relevant unchanged loading, source fitting and scoring steps from scripts/natural_shift.py and scripts/benchmark_multi.py at https://github.com/deb2019/SAT-multidomain. Dependencies for that step also include scikit-learn. No SMOTE refit is required for this pairwise comparison. Use the authors' prepared bank file pre_bank_marketing.csv; a fresh generic one-hot encoding gives slightly different costs. Diabetes used UCI diabetic_data.csv; card transactions used Kaggle kartik2112/fraud-detection, fraudTrain.csv and fraudTest.csv. The committed repository results/natural/{case}_lr.csv files are supplied here as the three reference CSVs.

Counts: N=batch size, D=number of changed predictions, K=positives among D, lower=1 if SAT lowers the threshold. src and sat are absolute mean costs. All 34 source/Point-SAT costs agree with the repository to 1e-9. The old_gate column is the published robust-SAT cost. Oracle chooses the cheaper of two thresholds retrospectively.

Sampling is uniform without replacement; budget counts only newly requested labels, not their financial or time cost. At most D labels are used by targeted sampling. For lower thresholds, source minus SAT cost per batch is (6K-D)/N; reverse sign for raised thresholds. Against the composite null of zero or negative benefit, use the one-sided upper hypergeometric tail at floor(D/6) for a lowered threshold and lower tail at ceil(D/6) for a raised threshold, alpha=.05. On rejection deploy SAT, otherwise keep source. Ties in classifier scores follow the original >= rule. For the random baseline first draw from the full batch, then apply the same test conditional on the number drawn in D. This isolates the sampling choice. Compute exact switch probabilities by summing possible draws, not Monte Carlo. Expected costs use full-batch counterfactual classifications, including audited cases. These results do not measure future-batch generalisation, annotation delay, label purchase cost or statistical superiority over active-comparison methods.

17 batches: 5 beneficial, 11 harmful, 1 tie. Equal weighting of periods within each sign, excluding the tie. At budget 50 the targeted beneficial-switch rate is 65.19% versus 19.94% for random; harmful-switch rates 0.386% versus 0.190%. The advantage in beneficial approvals is concentrated in the simulated transactions and two small disagreement regions can be fully enumerated. This is pilot evidence only.
